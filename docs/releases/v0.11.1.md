## v0.11.1

### 确定性的双识别码握手
- 移除 v0.10 / v0.11 中的启发式交互流程：不再先等待数秒尝试仅凭 INVITE 建连，再决定是否显示 REPLY 识别码。
- 建立连接前固定交换紧凑的 `P2PF-INVITE-...` 和 `P2PF-REPLY-...` 两个识别码，交换完成后才开始真正的 QUIC 建连。
- 创建方只有在粘贴并校验 REPLY 识别码后，才启动真正的 QUIC 监听和连通性流程。
- 加入方读取 INVITE 后立即生成 REPLY，然后静默等待创建方粘贴该识别码。
- 消除 REPLY 提示或等待文字可能一直残留、直到用户再次按回车才刷新的界面竞态。

### Candidate 交换后的路径选择
- 开始选择连接路径之前，双方已经拿到完整的 candidate 集合。
- 可全局路由的 IPv6 candidate 会获得一个很短的优先窗口，使双栈网络通常优先选择 `IPv6-DIRECT`。
- 如果 IPv6 被防火墙过滤或不可达，IPv4 candidate 会自动作为回退路径继续尝试。
- IPv4 NAT 打洞直接使用已经交换完成的 STUN / host candidate，不需要额外的人工信令或第三个识别码。

### 识别码
- 保持 v0.11 的紧凑二进制识别码格式。
- `P2PF-INVITE-...` 仍由创建方生成并发送给加入方。
- `P2PF-REPLY-...` 仍由加入方生成并回传给创建方。
- 线上的协议格式和识别码编码继续与 v0.11.0 兼容；本版本主要修改交互式连接状态机，使连接流程固定、确定。
