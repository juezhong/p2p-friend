## v0.11.3

### IPv6 防火墙穿透
- 双方拥有 IPv6 candidate 时，不再只依赖加入方向创建方发起 QUIC。
- 创建方和加入方都会从各自选定的 IPv6 UDP socket 主动向对端 IPv6 candidate 发送探测包，用于尽量打开家用路由器的 stateful IPv6 firewall 状态。
- IPv6 仍然具有优先级；如果 IPv6 探测后仍不可达，现有 IPv4 直连 / NAT-PUNCH 会自动接管。
- IPv6 不涉及 NAT 映射，因此成功链路仍显示为 `IPv6-DIRECT`；status 中会额外标记 IPv6 socket 正在进行“防火墙探测”。

### 传输任务来源显示
- 修复传输仲裁错误信息中“本机发起 / 对端发起”的视角问题。
- Linux 发起 `get` 时，Windows 端若因为该任务占用而拒绝新的传输，会正确显示为“对端发起”。
- RPC 返回忙状态时会按请求方视角翻转 owner，不再把仲裁端的 local / remote 文案原样传给另一端。

### 兼容性
- 不增加新的识别码，不修改 INVITE / REPLY 格式和协议版本。
- 保持两次识别码交换、IPv6 优先和 IPv4 fallback 的确定性流程。
