## v0.12.0

### P2P 穿透增强

- 建链从“创建方监听、加入方拨号”升级为双方同时 **QUIC Listen + Dial**。创建/加入角色不再决定 QUIC 握手方向，程序会自动竞争可用直连路径，并用一致的方向偏好避免两条连接同时保留。
- UDP punch 探测加入会话级安全校验：使用 256-bit session token 计算 HMAC-SHA256，并校验角色、时间戳和随机 nonce；重复 nonce 会被拒绝，运行时动态 candidate 也有数量上限。
- 对通过认证的 punch 包读取真实 UDP source endpoint，并加入 **peer-reflexive（prflx）candidate**。当 STUN 映射地址与实际发往 Peer 时的 NAT 映射不同，程序可以继续尝试真实观察到的端点。
- IPv4 STUN 改为在同一个 QUIC UDP socket 上查询多个 STUN endpoint。若不同目标观察到不同公网映射，会标记为 endpoint-dependent；多个有效 srflx 地址会一起参与候选竞争。
- 新增可选的显式 UDP 端口映射候选，依次尝试 **PCP、NAT-PMP、UPnP IGD**。成功后将公网映射作为 portmap candidate；失败会自动降级到 IPv6、host、STUN 和 punch 路径，不影响正常建连。
- IPv6 继续优先尝试直连，并通过双向安全 punch 尽量打开 stateful firewall 返回路径。

### 协议与安全

- Signal / ALPN / 应用会话协议升级到 **v12**。
- `P2PF-INVITE` 与 `P2PF-REPLY` 现在都携带本端临时 QUIC TLS 证书 SHA-256 指纹，使双方都可以安全充当 QUIC server。
- v12 识别码新增 `portmap` candidate 类型；`prflx` 只在运行时由通过认证的 punch 动态产生，不会从未认证网络数据直接写入。
- v0.12.0 与 v0.11.x 的识别码协议不互通；版本不匹配时会明确报错。

### 传输保持不变

- 文件、目录、RPC 和控制消息仍使用现有 **可靠 QUIC Stream**；本版本没有把文件数据改成 QUIC DATAGRAM。
- 仍然不使用 TURN / relay / 中继服务器，业务数据只在两个端点之间直接传输。
- 没有 relay 的前提下，双对称/endpoint-dependent NAT、严格 CGNAT、完全禁止 UDP 等网络仍可能不存在可用直连路径；本版本目标是尽量打通“网络本身存在直接路径”的场景，而不是宣称所有 NAT 组合都能 100% 直连。

### 诊断

- `status` 能区分实际 QUIC 主动/监听方向，并识别 HOST、STUN/NAT-PUNCH、peer-reflexive 与显式端口映射路径。
- 内部保存 STUN 映射稳定性和 PCP/NAT-PMP/UPnP 映射信息，便于定位不同路由器/NAT 环境下的建链行为。
