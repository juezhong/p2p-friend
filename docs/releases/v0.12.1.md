## v0.12.1

### 创建 / 加入识别码速度优化

- 修复 v0.12.0 中候选收集串行等待导致的邀请码、回传码生成明显变慢的问题。
- 本机 IPv4 / IPv6 host candidate 仍然立即收集；Multi-STUN 与显式端口映射改为并行探测。
- 三个 STUN Binding Request 会先并行发出，再通过 transaction ID 在同一个 UDP socket 上统一接收响应，不再按 900ms × 3 串行叠加等待。
- PCP、NAT-PMP、UPnP IGD 改为并行竞争，最先成功的显式端口映射直接使用，其余路径会取消并清理已经创建的多余映射。
- 所有增强候选共享约 1.5 秒统一时间预算；即使 STUN、PCP、NAT-PMP、UPnP 全部不可用，也不会再把各自超时累加到数秒以上。

### 功能保持

- 保留 v0.12.0 的双向 QUIC Listen + Dial、authenticated UDP punch、peer-reflexive（prflx）candidate、Multi-STUN NAT 映射观察、PCP/NAT-PMP/UPnP portmap candidate。
- 不改变 P2PF-INVITE -> P2PF-REPLY 使用方式。
- 不增加 TURN / relay / 中继服务器，业务数据仍然只在两个端点之间直接传输。
- 文件、目录、RPC 和控制消息仍然使用可靠 QUIC Stream，本版本没有改为 QUIC DATAGRAM。
- Signal / ALPN / 应用会话协议仍为 v12，因此 v0.12.1 与 v0.12.0 识别码保持兼容。
