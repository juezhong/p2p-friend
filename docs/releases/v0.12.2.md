## v0.12.2

### 修复双向 QUIC 路径竞速

- 修复 v0.12.x 在多条 QUIC 路径同时成功时，淘汰 loser 会误调用完整 session Close，进而关闭共享 UDP socket / quic.Transport / listener，导致已经选中的 winner 随后报 `quic: transport closed` 的问题。
- 新增只关闭单条 QUIC path 的内部关闭逻辑；只有最终会话退出才关闭 rtcPeer、UDP sockets 和端口映射。
- 新增双向 `connectQUIC()` 同时运行后继续完成应用认证和数据读写的回归测试，专门覆盖 winner 不应被 loser cleanup 带死的场景。

### LAN 直连优先

- 不再仅靠 candidate rank 决定优先级，而是根据本机 interface CIDR 判断远端 host candidate 是否真正位于同一子网。
- same-subnet LAN host 立即发起 QUIC Dial；公网 host、portmap、srflx 按阶段稍后尝试，避免同一局域网中公网 NAT/hairpin 路径抢先赢得连接。
- prflx 是通过认证的 peer punch 实际观察到的 endpoint，会获得较快的重试时机。
- 单轮 QUIC candidate Dial timeout 从 4 秒收紧为 2 秒，让新发现的 prflx 更快进入下一轮。

### 更快的识别码生成

- candidate gathering hard deadline 从约 1.5 秒收紧到约 1.2 秒。
- Multi-STUN 仍保留，但两个有效 STUN 响应已经足够判断 stable / endpoint-dependent，不再为了第三个 STUN 一直等待到 hard deadline。
- 第一个有效 STUN 响应已经提供可用 srflx；若第二个响应未及时到达，只再等待约 220ms。
- 一旦已经得到可用外部 candidate，其余 discovery 只获得短 grace；若检测到 endpoint-dependent 映射，则会给 PCP/NAT-PMP/UPnP 更长一点机会，因为此时显式端口映射的价值更高。

### Port mapping 保留

- PCP、NAT-PMP、UPnP 没有删除，仍然作为无 relay 条件下的重要公网直连增强。
- portmap 不会抢占真正的同网段 LAN fast path。
- 竞速 loser 不再触发 peer.Close，因此不会因为关闭其他 QUIC path 而提前删除 winner 可能依赖的显式端口映射。

### 兼容性与传输

- Signal / ALPN / 应用会话协议仍为 v12，因此 v0.12.2 与 v0.12.0 / v0.12.1 的识别码保持兼容。
- 仍然不使用 TURN / relay / 中继服务器。
- 文件、目录、RPC 和控制消息继续使用可靠 QUIC Stream。
