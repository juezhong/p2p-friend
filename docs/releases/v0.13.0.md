## v0.13.0

### 高吞吐文件传输流水线

- 重构大文件传输热路径：发送端不再按“读取一批 -> 并行发送一批 -> WaitGroup 等整批完成”的方式停顿，改为持久 data-lane worker + 有界队列，磁盘读取、SHA-256、QUIC 加密/发送可以持续重叠。
- application data chunk 上限从 256 KiB 提升到 1 MiB，用更少的 Write、allocation 和 payload copy 提高大文件吞吐。QUIC 仍会按路径 MTU 自动拆分 UDP packet。
- 发送端使用约 64 MiB 的 pooled buffer window，不随文件大小增长；1 GiB、100 GiB、1 TiB 文件都维持有界用户态内存。
- 发送端改为顺序 file.Read，并利用操作系统 readahead；SHA-256 与这次唯一的文件读取同步完成，不再传输前额外扫描整个文件。

### 接收端顺序写与有界内存重排

- 4 条 QUIC data stream 不再直接争抢一个 transfer mutex 执行乱序 WriteAt。
- 网络读取与磁盘写入解耦：data lane 持续接收 pooled 1 MiB chunk，进入有界 reorder window。
- reorder window 使用全局 credit 硬限制 channel + pending map 总量约 64 MiB；窗口满后停止继续读取 QUIC stream，由 QUIC flow control 自然向发送端施加 backpressure。
- 专用 writer 只把从 offset 0 开始连续的数据顺序写入临时文件，使磁盘 I/O 更接近普通顺序写，并把大容量 dirty-page 缓存交给 Linux / Windows / macOS page cache。
- 接收端 SHA-256 与顺序 file.Write 同时完成，不再传完后重新读取整个 .part 文件计算校验。

### QUIC / 运行时升级

- Go toolchain 从 1.23 升级到 1.26。
- quic-go 从 v0.53.0 升级到稳定 v0.63.0。
- gateway 升级到 v1.1.1，go-nat-pmp 升级到 v1.1.0；goupnp 与 STUN 保持稳定版本。
- QUIC stream receive window 提升到 32 MiB initial / 128 MiB max；connection receive window 提升到 64 MiB initial / 512 MiB max，减少高速或高 RTT 路径受到应用层 flow-control window 限制的概率。
- 文件数据仍然使用可靠、加密的 QUIC Stream；不关闭 TLS 1.3，也不改用不可靠 QUIC DATAGRAM。

### NAT 穿透保持

- 保留双方 QUIC Listen + Dial、same-subnet LAN fast path、authenticated punch、prflx、Multi-STUN、PCP、NAT-PMP、UPnP 和无 relay 直连策略。
- v0.12.2 修复的 path-racing loser 生命周期逻辑继续保留。

### 协议兼容性

- Signal / ALPN / 应用协议升级到 v13。
- v13 的 data chunk 上限和传输流水线语义与 v12 不同，因此 v0.13.0 不与 v0.12.x 识别码互通；版本不一致会在信令阶段明确拒绝，而不是连接后传大文件时才失败。
