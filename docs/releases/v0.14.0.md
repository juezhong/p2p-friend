## v0.14.0

### 多 QUIC Connection 并行传输

- 在 v0.13 有界内存流水线基础上，把网络并行从同一个 QUIC connection 内的多 stream 升级为最多 4 条独立 QUIC connection。
- 主 QUIC 保留 control + 1 条 data stream；认证完成后在同一个 UDP socket / quic.Transport / NAT mapping 上额外建立最多 3 条 data-only QUIC connection。
- 额外 data connection 不重新做 STUN、UDP punch、PCP/NAT-PMP/UPnP，也不新开本地 UDP 端口。
- 每条 QUIC connection 使用独立连接状态和拥塞状态；大文件 chunk 通过共享队列由空闲 worker 动态领取，快 connection 会自然承担更多数据。
- 某些网络不允许额外 data QUIC 时会自动退化到已经成功的数据连接，不影响 control session。

### 文件流水线

- 保持 1 MiB pooled chunk、约 64 MiB 有界发送队列和约 64 MiB 接收 reorder window。
- 文件仍然只顺序读取一次，发送端 SHA-256 与读取同步进行。
- 接收端多 QUIC reader 并行收包，但统一重排后只做顺序 file.Write，并同步计算 SHA-256。
- 磁盘大容量缓存继续交给操作系统 page cache / dirty-page writeback。

### 目录进度修复

- 修复目录 GET/PUT 时进度条使用整个目录 Total 计算当前文件百分比的问题。
- 目录传输现在同时显示当前文件大小/百分比和目录总大小/总百分比。
- 动态进度继续在同一终端行刷新；只有文件完成并切换下一文件时才换行，不会让 chunk 看起来像一块一块单独输出。

### 协议

- Signal / ALPN / 应用协议升级到 v14。
- v0.14.0 需要两端都使用 v14；旧版识别码会在信令阶段明确拒绝。
- NAT traversal、LAN fast path、authenticated punch、prflx、Multi-STUN、PCP/NAT-PMP/UPnP 与无 relay 策略保持。
