## v0.14.2

### 修复局域网误选 NAT-PUNCH

- 修复双方明明处于同一局域网、信令也包含 `192.168.x.x` HOST candidate，却可能因为公网 srflx QUIC 握手更快而误选 NAT hairpin 的问题。
- `candidateRank` 不再只是信息性排序；检测到同子网 HOST candidate 后，主连接先进入约 1.2 秒 LAN 独占探测阶段。
- LAN 独占阶段内，公网/NAT 路径即使先握手成功也只作为 fallback 暂存，不允许抢占主路径。
- LAN 确认不可达后，才恢复 IPv6 公网、portmap、prflx、srflx 等现有 fallback。
- LAN 判断基于本机真实接口 IP + netmask，而不是简单把 RFC1918 私网地址都当作同一局域网。
- 同一子网的全局 IPv6 也会正确显示为 `IPv6-LAN`。

### 兼容性

- wire protocol 继续保持 v14。
- 保留 v0.14.1 的多 UDP flow data stripes、独立 source port fallback、STUN/punch/portmap 行为。
