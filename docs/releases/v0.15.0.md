## v0.15.0

### LAN 选路在识别码阶段确定

- HOST candidate 现在携带真实接口 prefix length，例如 IPv4 /24、IPv6 /64。
- 双方拿齐 INVITE/REPLY 后直接做 mutual subnet 判断；只有双方 prefix 都确认彼此属于同一子网，才进入严格 LAN 模式。
- 严格 LAN 模式只建立 LAN HOST 主 QUIC，不启动 srflx / portmap / NAT punch 竞速，因此公网 NAT hairpin 不再抢走本地路径。
- 如果 mutual LAN 已确认但 LAN QUIC 仍失败，会明确报告局域网链路/防火墙/AP/VLAN 隔离问题，而不是静默绕公网。
- 不存在 mutual LAN 时没有任何 LAN 等待，IPv6 direct、portmap、prflx、srflx/NAT punch 按现有方式直接并发竞争。

### 稳定二进制识别码基线

- 当前识别码本来已经是二进制；v0.15 进一步改成长期稳定 binary envelope，而不是引入 protobuf 额外依赖。
- 外部继续使用 P2PF-INVITE- / P2PF-REPLY-，以后产品版本号不再进入识别码格式。
- envelope 使用 capability bitmap 协商功能；candidate record 有长度前缀，未来可跳过未知扩展；顶层也保留 extension area。
- INVITE 保留完整 256-bit session token；REPLY 不再重复 32-byte token，只携带 16-byte HMAC session binding，因此回传码更短。
- TLS fingerprint、IPv4/IPv6 raw address、port、candidate type、HOST prefix 都以二进制保存，再做 Base64URL，避免文本 IP/JSON/protobuf tag 的额外开销。

### 稳定传输标识

- QUIC ALPN 改为稳定 `p2p-friend/stable`。
- 应用层认证 magic 改为稳定 `P2PF-STABLE`。
- authenticated punch magic 也不再跟随产品版本号变化。
- v0.15 是新的稳定协议基线，因此与 v0.14.x 不互通；从 v0.15 起产品版本升级不应再自动打断识别码兼容性。

### 保留

- 多 STUN、PCP/NAT-PMP/UPnP、authenticated punch、prflx、无 relay。
- 最多 4 条独立 QUIC data connection / 多 UDP flow。
- 1 MiB pooled chunk、有界 reorder window、顺序写盘、单遍 SHA-256。
