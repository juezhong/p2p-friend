## v0.15.3

### 修复 QUIC winner 竞态

- 修复创建方使用 `connectQUIC()`、加入方使用 `waitConn()` 时 winner 仲裁不对称的问题。
- 加入方现在与创建方使用一致的方向偏好：JOIN 优先 outbound，HOST 优先 inbound。
- 避免一端已经进入应用认证后，另一端把该连接作为 race loser 关闭并出现：`read authentication magic: Application error 0x0 (remote): preferred path won`。
- Dial 重试只在真正的 outbound 尝试结束后重置状态，高频 punch 只启动一次，避免重复 goroutine。

### 修复跨 NAT 的 LAN 误判

- HOST prefix 重叠现在只作为 LAN 路径优先提示，不再作为“已确认同一局域网”的依据。
- 两个不同 NAT 后的主机即使都使用 `192.168.1.0/24`，也不会再被强制进入 strict-LAN 并报：`检测到同一局域网，但 LAN QUIC 建连失败`。
- 只有候选集合中存在疑似 LAN HOST 时，才给其它路径 150ms head start；纯公网场景继续保持 0 延迟全并发。公网 IPv6、显式端口映射、STUN / prflx / NAT punch 始终保留自动 fallback。

### 修复 data stripe fallback

- 独立 UDP source port 的 data stripe 使用单独的短超时预算。
- 如果严格 NAT / 防火墙阻止独立 source port，剩余总预算会用于复用主 UDP socket 的 fallback。
- `1 primary + 3 data stripes` 仍是最多 4 条 QUIC data connection 的正常设计。

### 兼容性

- stable binary envelope、ALPN、应用认证 magic、capability bitmap 均保持不变。
- v0.15.0 ~ v0.15.3 的识别码协议继续兼容。
