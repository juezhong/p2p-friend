## v0.15.4

### 提升长时间大文件传输稳定性

- 修复 v0.13 流水线重构后长期发送热路径绕过保守/自适应发送参数的问题。
- 应用层 data lane 预取从每 lane 16 个 1 MiB chunk 降到 2，避免在 QUIC 自身发送缓存之外再形成约 64 MiB 的突发队列。
- Windows 持续传输使用 128 KiB application chunk、最多 2 条主动 data lane、200 us pacing，降低 Winsock UDP send queue 压力。
- Linux/macOS 继续保持最多 4 lane、1 MiB chunk 的高速路径。

### data lane 故障自动降级

- 单条 data lane 写失败后不再立即取消整个文件传输。
- 故障 lane 会从当前 session 调度中移除，同一 chunk 自动重试其它健康 lane。
- 所有 data lane 都不可用时，自动回退到 control stream 的 `frameData` 可靠传输路径。
- data lane 失败不会主动关闭 control connection，因此 shell/session 可继续存在。

### 改善断链诊断

- `get` 因主连接关闭失败时不再只输出 `connection closed during get`。
- 现在会保留并附带底层 QUIC/UDP close error，便于区分网络不可达、idle timeout、对端退出、UDP 队列等原因。

### 测试

- 新增 data lane 写故障注入测试，验证自动降级后文件 hash 正确且 session 不关闭。
- CI 新增 `windows-latest` 真机 QUIC sustained transfer 测试。
- Windows CI 使用 128 MiB 文件实际经过 QUIC/UDP 多连接持续发送，而不是只做 Windows 交叉编译。

### 兼容性

- stable binary envelope、ALPN、应用认证 magic、capability bitmap 均保持不变。
- v0.15.x 识别码协议继续兼容。
