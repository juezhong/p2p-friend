## v0.16.0

### 控制面 / 数据面彻底分离

- 双方都支持 v0.16 capability 时，主 QUIC 只保留 control stream，不再承载普通文件 payload。
- RPC、目录操作、取消、传输元数据、累计 ACK、会话 keepalive 全部留在主控制 QUIC。
- 文件数据使用最多 4 条 data-only QUIC；主控制连接不计入 data lane 数。
- 单条 data QUIC 关闭、超时或写失败时，只移除该数据链路并后台重建，不主动关闭主会话。

### ACK + 自动重传

- 每个文件增加独立 file ID，避免目录传输中旧数据链路的迟到重传污染下一个文件。
- 接收端只对已经按 offset 连续写入临时文件的数据发送累计 ACK。
- 发送端以 4 MiB 有界窗口保留未确认范围；ACK 超时或数据链路重建后自动重传未确认窗口。
- 即使 QUIC `Write()` 已返回成功、随后 data QUIC 才断开，未真正落盘的数据仍可由 ACK 缺口触发重传。
- 重复 chunk 在接收端安全丢弃并重新发送当前累计 ACK。

### 可重建 data QUIC

- data lane 由独立生命周期管理器维护，编号 1~4。
- 主动端持续修复缺失 lane；监听端持续接受重建后的 data-only QUIC。
- data lane replacement 不触碰主 control QUIC。
- 所有 data lane 暂时不可用时，文件传输等待重建，不再把大块 payload 回退到 control stream。

### Windows 自适应加速

- Windows 不再固定锁死在 2 lane / 128 KiB。
- 初始档位为 2 lane / 128 KiB，稳定窗口会快速上探：3 lane / 256 KiB -> 4 lane / 512 KiB -> 4 lane / 1 MiB。
- 只有连续 3 次数据面失败，或连续 3 个明显吞吐退化窗口，才会降低档位。
- 最高档仍为 4 条 data QUIC、1 MiB application chunk、无人工 pacing。
- Linux/macOS 保持高速起步，同时使用同一 ACK / 重传 / lane-rebuild 机制。

### 测试

- `go test ./...`、`go test -race ./...`、`go vet ./...`。
- Linux amd64/arm64、Windows amd64、macOS amd64/arm64 构建。
- Windows 真机 runner 执行 128 MiB QUIC 持续传输。
- Windows 长传测试会在传输过程中主动关闭一条 data-only QUIC，并验证文件仍完整、SHA-256 正确、主 control session 继续可执行 RPC。
- 新增自适应调速测试，验证 Windows 单次/两次错误不立即降档，连续错误达到阈值后才降档，并能重新升至 4 lane / 1 MiB。

### 兼容性

- stable signal envelope / ALPN / 应用认证 magic 保持不变。
- v0.16 通过 capability bitmap 协商新数据面；连接旧版 v0.15.x 时继续走原有 data-stream / stripe 兼容路径。
