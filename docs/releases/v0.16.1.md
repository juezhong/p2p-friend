## v0.16.1

### Linux 局域网吞吐回归修复

- 修复 v0.16.0 在两台 Linux 的 IPv4-LAN / IPv6-LAN 下明显慢于 v0.15.3 的问题。
- 根因是 v0.16.0 为 ACK/重传引入了固定 4 MiB stop-and-wait flight window：每发送 4 MiB 就必须等待累计 ACK，破坏了 v0.15.3 的深流水。
- v0.16.0 还会先完整读取/hash/构造整个窗口，再开始网络发送，使磁盘读取和 QUIC 写入无法重叠。
- Linux LAN 恢复 64 MiB 有界 flight window，对齐 v0.15.3 的约 4 lane × 16 chunk × 1 MiB 深度。
- Linux LAN 恢复每 lane 16 chunk 的生产者队列，让文件读取/hash 与 QUIC 写入并行流水。
- 首次发送直接把文件读取到最终 resilient frame buffer，去掉热路径中的额外 payload make+copy。

### 稳定性保持不变

- 主 QUIC 仍然是 control-only。
- data-only QUIC 仍可独立失败和自动重建。
- 接收端累计 ACK、未确认窗口重传、file ID 防迟到数据污染仍保留。
- Linux LAN 只是扩大“可重传的有界飞行窗口”，没有退回 v0.15.3 的无应用层 ACK 模式。
- WAN/direct 默认保持较小的 8 MiB flight window，避免高丢包链路一次重传过多数据。
- Windows 继续使用浅队列和原 v0.16 自适应策略，避免重新引入 Winsock UDP send queue 压力。

### 验证

- 新增 Linux 128 MiB sustained resilient LAN transfer CI。
- Linux 长传测试和 Windows 长传测试都会在传输过程中主动关闭一条 data-only QUIC，并验证传输完成、SHA-256 正确且 control session 仍可用。
- `go test ./...`、`go test -race ./...`、`go vet ./...` 和所有目标平台构建通过。
