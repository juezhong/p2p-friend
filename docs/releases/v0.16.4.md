# v0.16.4 — QUIC 可靠传输修复与接收路径优化

发布日期：2026-10-09

本次为 v0.16 系列补丁版本。保留现有 **QUIC Stream + 四条可重建 data-only QUIC**、累计 ACK、未确认窗口重传和 SHA-256 文件校验；**不更改传输线协议**，不引入 QUIC DATAGRAM。

## 修复与优化

- **修复发送端故障退出可能卡住的问题**：在 `sendFileResilientSliding` 清理时先取消发送 worker，再关闭队列并等待 worker 退出；增加取消回归测试。修复 commit：[`26e95fe6`](https://github.com/juezhong/p2p-friend/commit/26e95fe6c5f36d8c9148e1eb9158ef386e2180e4)。
- **减少接收路径多余的内存复制**：v0.16 的 QUIC 数据帧采用 28 字节 wire header，而写盘/重排缓冲沿用 20 字节起始偏移。现直接将 Stream payload 读入最终偏移，去掉每块一次、最大 1 MiB 的整块 `copy()`。优化 commit：[`fcc6b200`](https://github.com/juezhong/p2p-friend/commit/fcc6b200d1d6ff023ea15942ca48cdd5aef8ccf1)。
- **完善跨平台测试**：三平台原生 GitHub Actions runner 均完成 2 GiB PUT 和 GET，SHA-256 校验通过；macOS 测试中规范化系统临时目录 `/var` 的符号链接，不放宽生产路径安全校验。
- **清理 CI**：恢复原有日常测试、Race Detector、交叉编译，以及 Linux / Windows 128 MiB 长传输回归；移除每个 PR 自动触发的重型 ABBA 和 Windows M2 Profile 任务。2 GiB 三平台吞吐测试保留在手动触发的 **P2P 2 GiB performance** workflow 中。

## 性能：同一台 runner 的 A/B/B/A 实测

以下为 [CI #154](https://github.com/juezhong/p2p-friend/actions/runs/37888543879) 的 **2 GiB 单机 UDP Loopback** 性能，Go 1.26.8、4 条 QUIC data stripe。A 是旧接收复制实现；B 是本版去复制实现。各版本均测试两次，数据为两次吞吐量的算术平均，单位 MiB/s。

| 操作系统 / 架构 | PUT A | PUT B | PUT 差异 | GET A | GET B | GET 差异 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Linux amd64 | 195.04 | 236.55 | **+21.3%** | 248.91 | 249.56 | +0.3% |
| Windows amd64 | 79.70 | 80.81 | +1.4% | 99.46 | 96.37 | -3.1% |
| macOS arm64 | 207.06 | 235.94 | **+13.9%** | 188.16 | 188.78 | +0.3% |

**数据解读（重要）：** 同一 runner 上首次 A 比最后一次 A 明显慢，存在缓存预热和运行时状态变化；Windows 未显示明确性能改善，GET 还有小幅负向差异。这些数字是 **此轮实验观察值，不是稳定性能承诺，也不是相对于已发布 v0.16.3 的版本间提速**。不能用单机环回数据推断 WAN/LAN 真实链路速率或跨操作系统主机互传能力。Windows 专项诊断未找到值得在本版承担风险的进一步优化，因此保持现有 QUIC 参数。
