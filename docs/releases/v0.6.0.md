## v0.6.0 升级重点

v0.6.0 将连接与数据传输层从直接 TCP/TLS 升级为 **UDP + ICE + DTLS + SCTP DataChannel**，重点改善 IPv4 NAT 场景下的直接 P2P 建连，并为大文件加入多 stream 并行传输。

### 网络层

- IPv6 ↔ IPv6：ICE 自动选择可用 UDP 直连候选。
- IPv4 ↔ IPv4：加入 STUN server-reflexive candidate 与 ICE connectivity checks，支持常见 NAT 下的 UDP hole punching。
- 不配置 TURN / relay；无法建立直接 UDP 路径时明确失败，不会把文件交给中继服务器。
- 进入交互命令行前必须完成 ICE、DTLS、会话认证和全部 DataChannel 建立。
- 无自建信令服务器：双方通过聊天工具交换一次 OFFER / ANSWER。

### 传输层

- 1 条可靠有序 control DataChannel。
- 4 条可靠乱序 data DataChannel，共享同一 ICE/UDP P2P 路径。
- 大文件按 offset 分块，在 4 条逻辑 stream 上并行发送；接收端按偏移写入临时文件。
- UDP 丢包由 SCTP 可靠重传，不会把缺失数据当作成功文件。
- 不强制创建多个公网 UDP 端口，减少 NAT 映射数量并优先保证打洞稳定性。

### 文件完整性

- 发送端在传输前计算每个文件的 SHA-256 并输出校验值。
- 接收端收到全部数据并落盘后重新完整读取临时文件计算 SHA-256。
- 两端 SHA-256 完全一致后才重命名最终文件并报告完成。
- 校验失败、取消或传输异常时不会报告成功，并清理可安全清理的临时内容。

### 保留功能

- SFTP 风格的 `pwd/ls/cd`、`lpwd/lls/lcd`、`put/get`。
- 远端绝对路径与递归目录传输。
- 中文、空格路径与本地/远端 Tab 补全。
- `Ctrl-C` / `cancel` 只取消当前传输，会话继续保持。

### 兼容性

v0.6 使用 `P2P6-OFFER-...` / `P2P6-ANSWER-...` 信令码，与 v0.5 及更早连接协议不兼容；双方需要同时升级到 v0.6.x。
