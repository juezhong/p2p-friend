## v0.7.0 升级重点

v0.7.0 将 v0.6 的 WebRTC DataChannel 数据面替换为原生 QUIC/UDP，并继续保留 IPv6 直连和 IPv4 STUN/NAT 打洞。

### QUIC 数据面

- QUIC TLS 1.3、可靠重传、拥塞控制和流量控制。
- 1 条 control stream + 4 条并行 data stream。
- 大文件按 offset 并发发送，接收端使用 `WriteAt` 拼装临时文件。
- 应用层 chunk 从 48 KiB 提升到 256 KiB，QUIC 根据 PMTU 负责实际分包。
- QUIC 丢包恢复负责重传；最终 SHA-256 负责端到端完整性确认。

### UDP / NAT

- IPv6 直连候选。
- IPv4 本地候选 + STUN 映射候选。
- 双方同时发送 UDP hole-punch 探测。
- STUN、打洞和 QUIC 使用同一个 UDP socket，保持 NAT 映射一致。
- 不使用 TURN / relay；全部候选失败时明确连接失败。

### 性能

- quic-go 直接使用 `*net.UDPConn`，保留其底层 UDP 优化能力。
- 在 Linux/内核支持时可利用 UDP GSO、批量收包、ECN 与 PMTU 相关优化。
- 请求 16 MiB UDP socket buffer，并扩大 QUIC stream / connection receive windows。
- 4 条数据 stream 减少单 stream 队头阻塞并提升大文件 pipeline 并发。
- 控制命令和文件数据仍只使用一个 QUIC/UDP P2P 连接，不额外依赖 TCP。

### 完整性

- 发送前计算并输出 SHA-256。
- 接收完成后重新读取落盘 `.part` 文件计算 SHA-256。
- 两端完全一致后才重命名并报告完成。

### 兼容性

使用 `P2P7-OFFER-...` / `P2P7-ANSWER-...`，双方需要同时升级到 v0.7.x。
