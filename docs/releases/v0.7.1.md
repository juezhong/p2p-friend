## v0.7.1

v0.7.1 是 v0.7 QUIC 传输层的稳定性补丁，重点修复 Windows 发送大文件时可能触发 Winsock `WSAENOBUFS` / `queue was full`，以及连接成功后交互提示符偶尔落在空白状态行的问题。

### Windows QUIC 发送稳定性

- QUIC 协议仍建立 4 条 data stream，协议兼容 v0.7.0。
- Windows 发送端默认使用 2 条活跃 data stream，而不是同时向 4 条 stream 高速灌入数据。
- Windows 应用层 chunk 从 256 KiB 调整为 64 KiB。
- Windows 发送 chunk 之间加入极短的平滑间隔，降低瞬时 Winsock UDP send queue 压力。
- 应用层待发送 job queue 缩小为每个活跃 writer 最多一个排队 chunk，避免与 QUIC 自身的拥塞控制 / flow control 重复堆积大量数据。
- Linux 等平台仍使用 4 条活跃 stream 和 256 KiB chunk，不降低现有并发能力。

这不是给 Windows 固定限速：QUIC 仍负责 packet pacing、拥塞控制、重传和 PMTU；补丁只减少应用层一次性向 QUIC / Winsock 注入的突发量。

### 终端显示

- 不再依赖 `ESC[s` / `ESC[u` 保存和恢复光标。
- 使用显式上下移动和显示宽度重新定位输入光标。
- 修复部分 Windows Terminal / conhost 组合在刚进入会话时光标停在空白状态行、看起来没有 prompt 的问题。
- 异步日志和传输进度仍会恢复正在输入的命令。

### 错误输出

- 同一 QUIC transport 故障只输出一次主要错误，避免 4 条数据流同时失败时重复刷出相同错误。
- 对 Windows UDP send queue 耗尽错误给出更明确的提示。

### 兼容性

v0.7.1 没有修改 P2P7 信令和文件协议，和 v0.7.0 保持协议兼容。建议双方都升级到 v0.7.1，以获得相同的稳定性修复。
