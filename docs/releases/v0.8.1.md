## v0.8.1

### 终端显示修复
- 修复 Linux/tmux 和部分 Windows Terminal / conhost 下连接成功后只出现空白光标、看不到 `p2p[...]` 提示符的问题。
- 没有传输进度时，行编辑器不再创建/维护第二状态行。
- 有进度时改用更通用的 CRLF + Cursor Up 重绘，不再依赖容易产生兼容性差异的 CNL/CPL 行移动序列。
- 实际协商出的链路类型写入会话状态，prompt 和 `status` 都会显示。

### 连接交互
- 启动菜单去掉固定的网络实现说明。
- 只有连接最终超时时才提示交换“发起连接 / 加入连接”角色重试。
- 保留 v0.8 的响应式发起端 listener：连接码生成后立即 Accept 等待真实 QUIC 握手。
- 加入端继续由长生命周期连接管理器主动发起 QUIC 握手；远端尚未就绪时不会把第一轮失败当作最终失败。

### 链路显示
连接成功后的 prompt 会显示实际使用路径，例如：

```text
p2p[IPv6-DIRECT remote:/path]>
p2p[IPv4-DIRECT remote:/path]>
p2p[IPv4-LAN remote:/path]>
p2p[IPv4-NAT-PUNCH remote:/path]>
```

`NAT-PUNCH` 表示 UDP NAT hole punching；不使用 `TUN`，因为 TUN 指虚拟网络接口/隧道设备，并不是 NAT 打洞。
